# Conformance vectors (vendored)

Test data for `src/conformance/*.test.ts`. Do not edit these files: update them from upstream.

## `blueprint-vectors.tar.gz`: Cardano Blueprint ledger conformance vectors

- Source: [cardano-scaling/cardano-blueprint](https://github.com/cardano-scaling/cardano-blueprint)
  `src/ledger/conformance-test-vectors/vectors.tar.gz` at commit
  `0f0c17e1ca24b062c868d216ae50708fc19c83ab`. Byte-identical to
  [blinklabs-io/ouroboros-mock](https://github.com/blinklabs-io/ouroboros-mock)
  `conformance/blueprint-vectors.tar.gz` at commit `6bfd701ae86cc6b81ae1d044e14231a16efd63da`
  (the corpus Dingo pins: `ouroboros-mock v0.20.5-0.20261002194245-6bfd701ae86c`).
- SHA-256 `574ff7a17857dfc1f0cf477f7eb9eba1c2a0f901453396a779de4b2392ef6863`, 1 780 623 bytes
  (checked by `blueprint.test.ts`). 2 574 vector files and 78 protocol-parameter files,
  19.9 MB extracted; the tests read the archive in memory (`tar.ts`), nothing is extracted to disk.
- Licence: Apache-2.0 (cardano-blueprint `LICENSE` / `NOTICE`, ouroboros-mock `LICENSE`).
- Generated by the cardano-ledger fork
  [SundaeSwap-finance/cardano-ledger-conformance-tests](https://github.com/SundaeSwap-finance/cardano-ledger-conformance-tests)
  at `34365e427e6507442fd8079ddece9f4a565bf1b9` (`cabal test cardano-ledger-conway`): every
  transaction an ImpSpec test submits is dumped with the ledger state before it and, when the
  LEDGER rule accepted it, after it.
- Format: one JSON record per transaction under `eras/conway/impl/dump/<test>/<n>`:
  `cbor` (the transaction), `oldLedgerState` / `newLedgerState` (hex CBOR of a Conway
  `LedgerState`, protocol parameters replaced by the SHA-256 of their CBOR), `success`,
  `testState`. `pparams-by-hash/<hash>` holds the 31-field Conway parameter record. The UTxO
  map is MemPack (`TxIn` with a little-endian `TxIx` in this cardano-ledger version).

## `consensus/*.json`: ouroboros-mock consensus scenarios

- Source: blinklabs-io/ouroboros-mock `consensus/testdata/captured/*.json` at commit
  `6bfd701ae86cc6b81ae1d044e14231a16efd63da`. Apache-2.0.
- Seven scenarios captured from cardano-node peers on a private devnet (k = 6): each upstream
  peer's served ChainSync trace (RollBackward / RollForward with raw Conway headers) and the
  oracle's outcome (final tip, expected rollback point, downstream ChainSync messages).
  Format: ouroboros-mock `consensus/format/vector.go`.

## Updating

Copy the new archive / JSON files from the pinned upstream commit, update the commits and the
checksum here and in `blueprint.test.ts`, the expected counts in both tests, and re-run
`bun test src/conformance`.
